## 它解决什么问题

跑过 QQ 机器人都知道，真正的痛点不是"接上 QQ"，而是接上之后：

| 问题 | 这套东西怎么处理 |
|---|---|
| 聊久了上下文越滚越大，一天烧七块钱 | `context-guard`：上下文超线就换新会话，换之前把记忆和最近 20 句交接过去 |
| 换会话就失忆 | 四层记忆：长期事实 / 随身本 / 每日摘要 / 完整档案 |
| 聊久了记忆越攒越脏（重复、出戏台词、占位符） | `memory-tidy` 每天清垃圾 + 合并重复，清完复查到干净，删什么都记账 |
| 进程不知道什么时候就死了 | `supervisor` 管 9 个后台脚本，`stack-doctor` 盯着 QQ / 桥接 / DSH / 脚本 |
| 改了代码要手动重启 | 心跳锁 + 热重载，改文件 3 秒生效 |
| 出问题没人知道 | `self-check` 每天自查，`stack-doctor` 每 2 分钟巡检 |
| 余额耗尽了才发现 | `balance-watch` 每 30 分钟查一次，分四档提醒 |

## 架构

```
QQ 客户端                                  ← 你手机/电脑上那个，用来跟机器人聊
   ↕
NapCat (:3000 HTTP / :3001 WS)             ← 替你登录 QQ（非官方协议端，要管理员权限）
   ↕
qq-bridge (:3100 控制台)                    ← 把 QQ 消息翻译给 AI，再把 AI 的话发回去
   ↕
DeepSeek Harness                           ← AI 在这里说话（也在这里烧 token）

旁边还有几个"看着它们的人"：
  brain          主脑，一个入口管 9 个后台脚本（启动 / 守护 / 决策 / 状态 / 日志都在它这儿）
  stack-doctor   每 2 分钟体检一遍：QQ / 桥接 / DSH / 后台脚本，谁挂了拉谁
  stack-guard    只干一件事：确认主脑还活着（10 秒看一眼，别的都不碰）
```

一句话记住：**NapCat 管登录，桥接管翻译，DSH 管说话，主脑管别死。**

### 主脑默认就在跑，出故障它自己拿主意

装完不用手动开：登录后 20 秒，计划任务 `QQBotBrain` 用 `run-hidden.vbs` 静默拉起
`20-supervisor.bat`（启动文件夹里那份是兜底，两条路都会先撞上单实例锁，只会活一个）。
装的时候没管理员权限也没关系，自启任务注册不上，启动文件夹那份照样能把主脑拉起来。

```bat
node brain.mjs --status                 :: 谁在跑、重启几次、锁多久没心跳、最近 5 条决策
node brain.mjs --decisions              :: 最近 20 条决策（回答"它当时为什么动了手"）
node brain.mjs --once                   :: 起一遍就退，改完代码自测用
```

它的决策表（每一条都是真踩过才写的）：

| 看到什么 | 怎么办 |
|---|---|
| worker 崩了 | 5 秒后重启；锁冲突（退出码 3）等 30 秒 |
| 同一个 worker 10 分钟内崩 4 次 | 隔离 10 分钟 + 告警文件，别把日志和 CPU 刷爆 |
| worker 活着但锁 180 秒没心跳 | 判定卡死（同步调用/死循环），杀掉重来 |
| 日志里 `Cannot find module` | 不重启了，隔离 30 分钟，写出缺哪个模块 |
| 缺文件 | 跳过并记一笔，不刷屏 |
| `:3100` 断、`:3000` 通 | 拉起桥接；15 分钟内失败 3 次就退避 10 分钟 |
| `:3000` 断 | **不自己乱拉**（要一次 UAC，登录还有次数预算），交给巡检；同时确认巡检任务真的在跑（10 分钟没跑就 `/run` 它） |
| 旧 supervisor 复活 | 收掉它整棵树（两边各拉一套 worker 会互相抢锁） |
| 锁文件指向死进程 | 清掉 |
| 日志超过 8MB | 只留最后 1500 行 |

为什么不是"把 9 个脚本塞进一个进程"：那 9 个都是常驻定时任务，塞一起的话
一个未捕获异常、一次内存泄漏、一个卡死的同步调用会让**九个一起死**，连巡检都没人跑。
所以主脑只管"启动 / 守护 / 决策 / 状态"，每个脚本仍然独立进程，崩一个不连坐。
`stack-guard` 也只剩"主脑别死"这一件事——两处都动手会互相踩（谁先谁后看运气，日志还会说谎）。

### 三个脑：左脑管封号，右脑管运行，小脑管记忆和余额

「让服务活着」和「别把号搞没」是会互相顶的（QQ 掉了，右脑想立刻重登，左脑说今天次数到顶了）。
混在一段代码里写，最后一定是「谁后改的那行赢」，出事说不清哪条规矩被越过。所以拆成三个：

| 谁 | 管什么 | 能做什么 |
|---|---|---|
| 左脑 `hemis/left.mjs` | 安全/封号 | 只回「账号动作能不能做」：登录次数预算、23:00–07:00 不登录、刚等过验证码 45 分钟不撞、私聊不发群、空间每日上限、邮件每日上限 |
| 右脑 `hemis/right.mjs` | 运行逻辑 | 只提「该修什么」：补拉 worker、重启卡死的、拉桥接、催巡检、拉 NapCat（这条要左脑点头） |
| 小脑 `hemis/cerebellum.mjs` | 记忆/输入输出/余额 | 每天摘要没做就补、记忆涨到预算边上或出现脏数据就整理、余额低于 2 元进省聊、低于 1 元发一封提醒 |

主脑仲裁：右脑/小脑只能提，左脑只能否，主脑执行。**冲突时提案那一方自己下线**——
10 分钟内被否 3 次，它下线 15 分钟（右脑只留保命动作；小脑不再提记忆/邮件）。
左脑自己坏了（抛异常）就切到内置的最严策略：账号动作全禁，保命动作照做。

```bat
node brain.mjs --hemis       :: 三个脑现在什么状态、看到什么、最近几次冲突
```

### 桌面上只留一个「启动主脑」

NapCat 和桥接都归主脑了：`1-启动NapCat.bat` / `2-启动桥接.bat` 现在只做一件事——把主脑叫起来，
真正的启动决策在主脑里（桥接断了 20 秒内拉起；NapCat 连续 3 轮（约 1 分钟）没起来才提，
而且要过左脑的登录预算闸门）。所以桌面那两个快捷方式已经合并成一个 `启动主脑.lnk`，
旧的两个存在仓库 `archive/old-shortcuts/` 里留底。
### 主脑比所有脑都高一级：越权和维持

- **维持**（每 5 分钟）：磁盘剩不到 2GB 就直接清一轮垃圾（不等左手排队）；自己内存超过 400MB 就重启自己（急救员会拉回来）；左脑连续抛异常就重置它的计数，让它重新评估。
- **越权**：所有脑都说不行、但它判断「再不动手服务就没了」时才用。现在只开一条——NapCat 断了超过 3 分钟、30 分钟内本来是通的、30 分钟内没越权过。每次越权都记一条 `主脑-越权`，能查能追。
- **右手边还有手**：小脑负责「看出问题」（污染、重复、核心要点），动手的是左右手：

| 手 | 干什么 | 铁规矩 |
|---|---|---|
| 左手 `hands/left-hand.mjs` | 删无用文件/脚本 | 只碰明确是垃圾的（`*.tmp *.bak *.old *.out *.err`、轮转日志、过期二维码、旧版本目录）；**不是真删，是搬到 `trash/<日期>/` 并写 manifest**；不碰代码/配置/记忆/桥接/node_modules；每次最多 200 个、300MB |
| 右手 `hands/right-hand.mjs` | 删无用/重复记忆 | 只删「同一句话的重复」和纯污染（控制字符、乱码、只剩符号）；**删之前整份备份到 `chat-memory/backup-<时间>.json`**；走桥接 `memory-remove` 接口；一次最多 20 条 |

### 急救员：脱离主脑独立运行，专门把主脑救回来

`medic/medic.mjs` 不 import 主脑任何代码，只认两样东西：`brain.lock` 里的 pid 还活着吗、`brain.json`（主脑每 20 秒刷新）还新鲜吗。

- 主脑在线时：**保持安静**，只清「指向死进程的锁文件」、自己的日志别涨爆，然后什么都不碰。
- 主脑不在（死了或卡死）：按顺序救——① 直接拉 `brain.mjs` ② 清死锁再拉 ③ 杀掉卡死的主脑再拉 ④ 硬清场（清掉所有占锁的进程）再拉 ⑤ 还不行才写 `ALERT-主脑.txt` + 发一封邮件（每小时最多一封）。
- 开机自启：计划任务 `QQBotMedic`（登录后 25 秒）+ 启动文件夹兜底。它和主脑谁先起来都没关系，主脑有两个也只会活一个（单实例锁）。

```bat
node medic/medic.mjs --status   :: 主脑死活 + 急救员在不在 + 救过几次
```
### 嘴：默认闭着，只把「谁死了、谁摸鱼」报给主脑

眼只对急救员负责（救命用），急救员平时又不出声。所以主脑其实不知道别人活得怎么样——它只看到自己那 9 个 worker 和三个脑的返回值，看不到「眼是不是还活着」「急救员在不在」「哪个脑自己下线十分钟没恢复」。

`mouth/mouth.mjs` 就是补这一块的：每 30 秒汇总一遍，写 `state/mouth-report.json` 给主脑，主脑一拍到就记一条 `嘴报`（有死的、有摸鱼的、还是全部正常）。**它不动手、不重启、不删东西**，只有名单变化才写一行日志。

### 权限交接：急救员救不了时临时接管，其余器官辅助

- 主脑不在 → 急救员**临时拥有最高权限**：清障（坏 JSON、僵住的 worker 锁、涨爆的日志）、指挥左手清垃圾腾地方、拉起主脑。
- 救不动 → 写急救队列 `state/heal-queue.json`：`rescue-brain`、`revive-hemi`（哪个脑下线超过 15 分钟）。
- 主脑一起来 → **消费队列**：把还没复活的脑拉回来（`主脑-复活脑`），把救援任务标记闭环（`主脑-接回权能`），然后权能交还、急救员退回静默。
- 清场只碰 worker 的锁——`bridge.lock` 这种「本体锁」一律不碰（踩过一次：把桥接当垃圾杀了，主脑还得把桥接重拉一遍）。
### 眼、嘴、主脑：看到 → 转述 → 处置

- **眼**只观察、只写 `state/eye-findings.json`。**嘴**每 30 秒把「谁死了/谁摸鱼/能不能干活」连同**眼看到的东西**一起写进 `state/mouth-report.json`（日志里有一条 `转述眼：…`），主脑据此记 `嘴报`。
- **主脑可以处置任何器官**：嘴说谁死了、或者它自己发现某个器官锁里的 pid 不在了，就重拉（眼、嘴、急救员；worker 由右脑补拉）。
- **脑救不活就造一个新的**：同一个脑连续 3 轮救不回来，主脑用 `import('./hemis/xxx.mjs?gen=N')` 拿一个**全新的模块实例**顶上（`主脑-造新器官`），旧实例状态清零。日志里能查是第几代。
- **自律**：QQ 登进去以后，扫码框一律收掉（`主脑-自律：关掉扫过的二维码框`）；一直没人扫、开了超过 20 分钟的框也收掉，别赖在屏幕上挡事。

### 码过期？主脑自己把黑屏二维码糊上来

QQ 掉登录 / 二维码过期时（`:3000` 通、但 `get_login_info` 拿不到 user_id），主脑调 `tools/qr-screen.mjs`：

1. 确保扫码页服务在跑（`tools/qr-live.mjs`，码每 3 秒自己刷新，过期了会自动换新码）；
2. 用 `tools/qr-black.ps1` 开一块**全屏黑底大二维码**（WinForms，不依赖浏览器），二维码直接铺满屏幕，掏手机扫完就登进去；
3. 登录成功后它自己关，主脑也会主动收掉（`主脑-自律`）。

为什么不用浏览器：从脚本里拉浏览器，经常「进程起来了、页面一次都没被访问」—— 所以黑屏用 WinForms 画，靠心跳文件确认真的亮起来了。`qr-black.ps1` 保持纯 ASCII（PowerShell 5.1 读无 BOM 的 UTF-8 会按 ANSI 解析，中文标点直接把解析器搞崩）。
### 主脑自律·资源：谁占太高就压谁，压完记得松开

主脑每 60 秒采一次自己这套东西的占用（`Get-Process` 读 node/浏览器/powershell 的 CPU 秒数和内存），只认**自己拉起来的**那些：9 个 worker、眼、嘴、急救员、它自己。桥接、NapCat、QQ 一律不碰——动了就是拿服务换指标。

| 情况 | 主脑怎么做 |
|---|---|
| 内存 > 320MB 或 CPU > 25%，**连续两次** | 把那个进程的优先级降到 `Idle`（立刻见效、不打断它），记 `主脑-降占用` |
| 占用回落到阈值以下 | 优先级还原 `Normal`，记 `主脑-恢复占用` |
| 眼/嘴/急救员这种小东西涨到 200MB | 判定漏了（它们本来就几 MB）→ 重拉一份 |
| worker 涨到 600MB | 重启这个 worker |
| 主脑自己重启 | 启动时把继承下来的 `Idle` **全部还原**（不然被降过的 worker 会永远慢半拍） |

阈值都能用环境变量改：`BRAIN_RSS_WARN_MB` / `BRAIN_RSS_ORGAN_MB` / `BRAIN_RSS_RESTART_MB` / `BRAIN_CPU_WARN_PCT`——自测时把它们调小，就能把整条链路跑一遍。

状态页会多一行：`占用：worker:balance 66MB/0%  brain 66MB/2%  ...`
### 主脑的三条逻辑：理性、创造、喜悦

**理性**（每 10 分钟）：把「已经死了 / 没人用了」的脚本搬进 `trash/`（可捞回来），同时写一份**病因**进 `state/autopsy.json`：

```json
{ "at": "...", "rel": "stack-guard/stack-guard.mjs", "cause": "守夜人已被急救员取代", "verdict": "退役" }
```

搬之前先做**引用检查**（全仓扫一遍还有没有人提到它），还在用的一律不动。下次它再犯同样的病，主脑能直接查历史。

**创造**：同一类问题在最近决策里出现 **3 次以上**，而且现有工具覆盖不了，主脑就照着模板造一个小工具放进 `tools/gen/`（端口体检、日志裁剪、状态抓取）。规矩只有三条：**只新增、绝不覆盖；只写 `tools/gen/`；不碰核心代码**。造过什么记在 `state/created.json`。

**喜悦**：某个器官连续**正常运转满 7 天**，主脑给它一次激励 —— 24 小时内不压它（不降优先级、不因占用被压），并记进 `state/joy.json`（7 天内不重复发奖）。奖励只是「免检」，不是给它加活；出事照样按规矩处理。
### 五个器官：黑匣子、体温计、钱包管家、海马体、耳朵

都由主脑拉起和看护（`ORGAN_ENTRY` 里注册，不额外加计划任务），各自有独立锁和状态文件。

| 器官 | 干什么 | 出事时 |
|---|---|---|
| **黑匣子** `blackbox/` | 每 10 秒录一条快照（端口/主脑/三脑/worker/器官/余额/最后一条决策）到 `state/blackbox.jsonl` | 异常持续 60 秒开始记事故，恢复 60 秒后落 `archive/incidents/incident-*.md`（起因 + 时间线 + 最后的决策） |
| **体温计** `vitals/` | 问桥接「有没有未读 / 最后回话多久 / busy」，判断**她能不能回话**（端口通 ≠ 能说话） | 有人说话 180 秒没回、持续 10 分钟 → 写 `state/vitals-alert.json`，主脑重启桥接（15 分钟最多一次） |
| **钱包管家** `treasurer/` | 自己记余额样本，算**元/小时**和**还能撑几小时** | 预计 3 小时内烧完 → 直接写省聊策略 + `state/treasurer-alert.json`；余额回来再放开 |
| **海马体** `hippocampus/` | 按时间给记忆定生死：话题 30 天没提 → 遗忘候选（一次最多 3 条，走右手，先备份）；事实 90 天没确认 → 只标记「该复核」 | 写 `state/hippocampus.json`，主脑随时能看它准备忘掉什么 |
| **耳朵** `ears/` | 收你的回信，白名单指令：`状态` / `重启` / `扫码` / `省钱` | 只认你自己发的邮件，处理完标已读，回信每天最多 6 封 |

耳朵的凭据沿用掉线通知那套（`config.json` 的 `notify.mail` + `qq-mail-auth.dat` 的 DPAPI 授权码），不落明文；`node ears/ears.mjs --selftest` 能验证指令识别（不真执行）。

各器官自查：`--status`（黑匣子/体温计/钱包管家/海马体/耳朵都支持）。
踩过的坑（2026-10-30 晚上，记在这里省得再踩）：主脑和旧 supervisor 会各拉一套 worker，
两边抢单实例锁，结果是**主脑的 9 个子进程全因锁冲突退出，锁却被 supervisor 的 worker 占着**
—— `brain --status` 显示"全停了"，机器上却确实有 worker 在跑。现在主脑启动时会把旧
supervisor 整棵树收掉，并占住 `supervisor.lock`（旧 supervisor 起来就退出码 3），
两边只能活一个。`20-supervisor.bat` 看到退出码 3 也直接退出，不会每 5 秒克隆一个注定失败的进程。


## 别人下载下来能直接用吗

**能，但要先把那四样装好**（下载地址见下面的 [需要什么](#需要什么)）——这个仓库只做「接上之后」的那一层，机器人本体不在这儿。

### 已经处理掉的「换台电脑就坏」

这几处原来写死在我们自己机器上，现在都改成自适应的：

| 原来会坏的地方 | 现在 |
|---|---|
| 启动器里写 `node ...`，计划任务没有用户 PATH → 找不到 node | install 时解析 `node.exe` 绝对路径写进去 |
| `CHAT_KEY` 默认 `private:YOUR_QQ`，不手改就发错人 | 自动从桥接 `config.json` 的 `ownerQQ` 推出来 |
| NapCat 日志固定找 `<root>\napcat\napcat\logs` | 可用 `NAPCAT_DIR` 覆盖 |
| 启动脚本名字固定（`2-启动桥接.bat` 等） | `NAPCAT_BOOT_BAT` / `BRIDGE_BAT` / `SUPERVISOR_BAT` 可覆盖 |
| 中文直接写进 `.bat` → GBK 尾字节撞上 `|` `^` `&` 把命令拆断 | `.bat` 全 ASCII，中文放 `risk-notice.ps1` |

### 还是会有落差的地方

| 落差 | 说明 |
|---|---|
| **只有 Windows** | 脚本用 PowerShell + `netstat` + 计划任务，Linux 要重写 |
| **绑定了桥接的接口** | `dsh-qq-bridge` 的 `/api/socialV2/*`、`config.json` 字段名变了就要跟着改 |
| **默认目录结构** | 期望 `<root>/dsh-qq/qq-bridge-enhanced-v1.1.0/`，桥接换个名字要改常量 |
| **中文界面** | 提示都是中文，非中文 Windows 下 `.ps1` 可能显示乱码（功能不受影响） |
| **计划任务要登录** | 没开自动登录的话，重启后要有人登录才会自愈 |

## 部署后占多少资源

实测环境：**12 核 / 16 GB / Windows 11**，稳定运行 30 天的状态。

### CPU

```
整机平均         7.4%（12 核，约 0.9 个核）
  └ 其中我们的： 0.4%（QQ 1.9% + DSH 1.4% + DSH 1.1%，按单核算）
其余全是系统后台和 DSH 的界面渲染
```

**CPU 不是瓶颈。** 她那套脚本是「定时醒来干活」型，空闲时基本不占：

| 组件 | 频率 | 单次开销 |
|---|---|---|
| `stack-doctor` | 每 2 分钟 | 起一个 node 跑完就退，约 0.2 秒 |
| `archive` | 每 60 秒 | 读最近 80 条、追加一行 |
| `context-guard` / `balance-watch` / `budget-guard` | 几十分钟一次 | 一次 HTTP 调用 |
| `cron` | 每 30 秒 | 比一次时间戳 |

### 内存

```
整机已提交       8.6 GB / 16 GB
  └ 其中我们的： 708 MB（DSH 515 MB + QQ/NapCat 约 190 MB）
后台脚本全部    每个 20~40 MB，9 个合计约 280 MB
```

⚠️ **4 GB 内存的机器会比较紧**：Windows 自身 + DSH + NapCat 就要 6 GB 上下。建议 8 GB 起步。

### 磁盘

| 目录 | 占用 | 说明 |
|---|---|---|
| `napcat/` | **350 MB** | QQ 协议端本体，装完就不动了 |
| `dsh-qq/` | 28 MB | 桥接 + 依赖 |
| `archive/` | 0.4 MB | 聊天档案，一个月也就几 MB |
| `state/` `chat-memory/` `versions/` `reports/` | < 1 MB | 状态、快照、报表 |
| **整套合计** | **约 380 MB** | 不含 DSH 桌面程序本身 |

日志会自动轮转：单个 `.log` 超过 5 MB 改名成 `.1`，最多留 5 份；`token-usage.jsonl` 到 20 MB 才轮转。**不会无限膨胀。**

### 什么会随使用量增长

| 会涨 | 不会涨 |
|---|---|
| API 费用（每句话都要重算上下文） | CPU（空闲时几乎为 0） |
| 聊天档案和摘要（一天几十 KB） | 内存（进程数固定，不随消息量涨） |
| **DSH 会话记录（一天约 3 MB，最大的一块）** | 磁盘占用（日志有上限） |
| 聊天里的图片缓存（你发图才会涨） | 记忆本体（有上限，见下） |
| 备份目录（保留 7 天，自动清） | |

会话记录和图片缓存由 `session-janitor` 自动清：会话文件留 **60 天**、附件留 **90 天**（`SESSION_KEEP_DAYS` / `ATTACH_KEEP_DAYS` 可调，设 0 关闭）。
它只清「能再生的记录」，**记忆本体和聊天档案永远不碰**——所以她十年前说过的话仍然查得到。

### 弱一点的机器怎么办

- **2 核 4 GB**：能跑，但 DSH + NapCat 同时在会明显卡；建议关掉 DSH 的界面（只留后台）
- **内存吃紧**：`budget-guard` 和 `session-janitor` 可以停掉，省 60 MB，功能影响很小
- **不想装 DSH 桌面版**：不行，AI 那一层就是它

## 部署

### 0. 一键部署（先跑这个）

双击仓库根目录的 **`install.cmd`**（会提权一次），流程是：

**① 先体检这台电脑**：系统版本、CPU、内存、每个盘的剩余空间、UAC 级别、快速启动状态、已装组件（Node / DSH / 7-Zip）。哪项不达标当场说，不往下走。

**② 问安装位置（只问第一次）**：选好的目录记在

```
%LOCALAPPDATA%\qq-bot-stack\install.json
```

之后每次运行都读这条记录，**所有东西继续装到同一个位置**。要换位置，在提示里直接输新路径，或者加 `-Reset` 重新问。

**③ 复制 + 生成 + 注册**：脚本复制过去，按你填的 QQ 号生成启动器，注册「全栈体检」计划任务（每 2 分钟自愈），关掉自动睡眠和快速启动。

**④ 依次启动**：装完问你要不要现在启动，按 NapCat → 等 `:3000` 通 → 桥接 → 等 `:3100` 通 → supervisor 的顺序走，每一步都等端口真的通了才走下一步。

**生成的启动器会先打印风险提示**（封号风险 / 隐私 / 计费 / 不含人设 / 要一直开机），你输入 N 就不启动。无人值守调用时加 `-y` 跳过提示——守护脚本就是这么调的。

> 为什么风险提示不在 `.bat` 里写中文：GBK 汉字的尾字节会落在 `|`、`^`、`&` 这些 cmd 元字符上，把一行 `echo` 拆成两条命令，直接报错。中文一律放在 `risk-notice.ps1`（UTF-8 带 BOM），`.bat` 保持纯 ASCII。

**它不会装** Node、DSH、NapCat、桥接——这四样都得你自己装好，缺什么它会直接说缺什么，装完再跑一次即可。

命令行用法：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -TargetDir D:\qq-bot-stack -OwnerQQ 123456789 -BotQQ 987654321

# 只看不改
powershell -ExecutionPolicy Bypass -File install.ps1 -DryRun

# 忘掉记住的位置，重新问
powershell -ExecutionPolicy Bypass -File install.ps1 -Reset
```

### 1. 装 NapCat

1. 从 [NapCatQQ releases](https://github.com/NapNeko/NapCatQQ/releases) 下载 Shell 版
2. 解压到 `E:\qq-bot-stack\napcat\`
3. `launcher.bat` 需要管理员权限（它要注入 QQ 进程）

**免扫码登录**：启动时带 `-q 你的QQ号`，NapCat 会复用本地凭证跳过二维码。

```bat
call launcher.bat -q 123456789
```

> **NapCat 的 HTTP 接口是路径式**：`POST /动作名`，参数直接当 body。
> 不要写成 OneBot 文档里那种 `POST /` 带 `{action, params}` —— 这版 NapCat 会回一句
> `{"status":"ok","data":{},"message":"NapCat4 Is Running"}`，**看起来成功，其实什么都没做**。
> 不确定就用 `node tools/napcat-call.mjs get_login_info` 试一下。

### 2. 装 DSH + 桥接

见 [dsh-qq-bridge](https://github.com/h-D-ACE/dsh-qq-bridge) 的说明。

关键配置（`config.json`）：

```json
{
  "ownerQQ": YOUR_QQ,
  "allow": { "private": ["YOUR_QQ"], "groups": [] },
  "socialV2": {
    "wake": { "defaultMode": "active", "recommendedProbability": 0.7 },
    "tools": { "sendGroup": false, "reply": false, "listGroups": false }
  }
}
```

`allow.private` 只放你自己的号，群列表留空（本项目只做私聊）。

### 3. 部署本套件

把本仓库放到 `E:\qq-bot-stack`（或任意位置，但要改 `cron` 里的路径假设）。

```powershell
# 依赖
cd E:\qq-bot-stack
npm init -y     # 如果你要用到 node_modules 里的东西
```

### 4. 写人设

**这是最费时间的一步**，见 [`roles/README.md`](roles/README.md)。

### 5. 起服务

```
1-启动NapCat.bat        ← 手动点，过 UAC
2-启动桥接.bat          ← 起不来就等 stack-doctor 两分钟内拉一遍
20-supervisor.bat       ← 管后台脚本
```

| 每天几点跑哪些定时任务 | `cron/cron.mjs` 顶部那张表（03:30 补丁、04:00 备份、09:00 巡检…） | 改完 3 秒自动重启 |
| 滴眼药水提醒的节奏 | `EYE_DROP_OFFSETS`（默认 `2,10` 分钟，共 2 条）、`EYE_DROP_FROM_HOUR`~`EYE_DROP_TO_HOUR`（默认 4~12 点） | 改完 3 秒自动重启 |
| 余额提醒门槛 | `THRESHOLD_CNY`（最高档，默认 10 元），或 `balance-watch.json` | 下次检查（≤30 分钟） |
| 省钱提醒的时段和频率 | `PEAK_FROM` / `PEAK_TO`（默认 08:30~23:30）、`PEAK_STEP`（每多花 1.5 元提醒）、`PEAK_COOLDOWN_MIN` / `PEAK_MAX_PER_DAY` | 改完 3 秒自动重启 |
| 开放群聊 | 桥接 `config.json` → `allow.groups`（默认空 = 只接私聊） | 重启桥接 |
| 她能调用哪些工具 | 桥接 `config.json` → `socialV2.tools` | 重启桥接 |

表里的 `XXX` 都是环境变量：最省事的写法是在 `20-supervisor.bat` 里加一行 `set XXX=...`（它拉起的后台脚本都会继承），不想动启动器就用系统环境变量。改完把 supervisor 重启一次。

**桥接的 `config.json` 只在启动时读一次**，所以改完要重启桥接（控制台调 `/api/restart`，或重开 `2-启动桥接.bat`），不然改了没反应。

## 关键设计（为什么这么做）

### 记忆分四层，因为每层都会过期

```
长期事实   只增不删，上限 60 条     作息、口味、忌口、生日       ← 不会过期
随身本     话题 + 印象，14 天       正在聊的、对方的近况         ← 会过期
每日摘要   一天 3~4 条，永久保留     "昨天聊了什么"              ← 会过期
完整档案   每句话都存，永久         想翻旧账时全文搜索            ← 不会过期
```

话题会过期、摘要只留要点——**只有「长期事实」能保证"聊半年还记得你几点睡"**。所以那一层原则上只增不删：只在超出字数预算（默认 2200 字）时，才按重要度砍掉最不重要的几条，而且每条都记账。

> ⚠️ 有个坑：`facts` 要同时出现在**五个地方**才不会丢——保存白名单、加载、清理、换会话恢复、断电恢复。少一处，平时没事，换会话那天全没了。本项目五处都处理了，你自己改的时候留意。

### 记忆会自己清垃圾，但不许「悄悄少」

`memory-tidy` 每天 22:20 跑一遍，**清完会重新读回来再查一遍，脏就再清一轮，最多三轮**（`TIDY_ROUNDS`）。它认为的「垃圾」是这些：

| 类型 | 例子 |
|---|---|
| 占位符/脏数据 | `<BOT_NAME>`、`undefined`、`[object Object]` |
| 出戏/meta 台词 | 「作为一个 AI，我…」「根据聊天记录显示」 |
| 指令残留 | 「请把…」「输出 JSON」——模型把自己收到的提示词写进来了 |
| 只有语气词/符号 | 「嗯」「哈哈」「……」 |
| 重复 | 换个说法说同一件事：先按字面判，再让模型挑一遍，**要求它指出跟哪条重复、且两条字面重合度 ≥0.2 才准删** |

删得狠，所以三道保险：

1. 写回前把整份旧记忆存到 `chat-memory/tidy-<日期>.json`，随时能捞；
2. 删掉的每一条都记进 `state/memory-removed.log`（state 写不进去就落 `chat-memory/`）：原文 + 原因，一条不落；
3. **硬账**：每一类少了多少条，就必须有同样多的删除记录——对不上就整轮不写、保留原样。

> 2026-10-28 的教训：一次整理后「哥」的印象凭空没了，日志里一条删除记录都没有（它是在中间环节丢的）。从那以后加了第 3 条硬账：宁可这次不整理，也不许悄悄少。

**记忆也有预算**：事实总量超过 `FACT_BUDGET_CHARS`（默认 2200 字）时，按重要程度砍——带数字/日期/作息/健康/口味的留着，「今天/刚才」这类时效性的先走。因为**记忆每句话都要重发一遍**，多 1000 字就是每轮多花约 1000 token；宁可少而精。

**每天还会体检**：`self-check` 用同一套规则（`lib/memory-rules.mjs`，memory-tidy 和 self-check 共用）查四件事——有没有垃圾、体积有没有超预算、长期事实有没有一夜暴跌、上次整理记录是否正常。暴跌超过三成就报问题，不会等到她"失忆"才发现。

**空间上真正的大头不是记忆**：记忆本体几十 KB，会话记录一天 3 MB。所以 `session-janitor` 保留 60 天会话文件、90 天附件，其余清掉；记忆和档案不碰。

### 欠账单独记一笔，因为摘要会把数字压糊

记忆是摘要，而摘要的本职就是压缩——「欠鸭腿十根 + 卤香两只，打五折」这种账被压过一次就对不清了。2026-10-29 真踩到：账在记忆里只剩一坨「鸭腿债：摸尾巴换十根盐焗鸭腿+水煮肉片多放辣（打五折），另有两隻卤香鸭腿，全没兑现」，十根还是两只、五折打在哪笔，全靠猜。

所以欠账单独走一条道，**它还是一行 `fact`，只是格式固定**：

```
欠账｜内容×数量｜YYYY-MM-DD[｜已结]
例：欠账｜盐焗鸭腿×10+水煮肉片(多放辣)+卤香鸭腿×2｜2026-10-28
```

四条规矩：

| 规矩 | 为什么 |
|---|---|
| 只记未结的，还清了就把那条 `fact` 删掉 | 账本上不留「已结」占预算；删之前同样进审计日志 |
| `memory-tidy` 不许压它：不进模型压缩、不进重复复审 | 模型分不清「鸭腿×10」和「鸭腿×2」是两笔还是一笔——让它判重就是替人赖账 |
| 唤醒时单独一段【欠账】，标「欠了几天」 | 账目要能翻出来对，不能混在普通事实里当印象看 |
| 独立预算 `DEBT_BUDGET_CHARS`（默认 600 字），超了按日期丢最老的 | 账目只增不减，抢普通事实的预算会把别的记忆挤掉；丢的每一笔都写 `memory-removed.log` |

`memory-tidy --selftest` 专门测这四条（规范化、同文去重、已结划掉、超长保日期、超预算丢最老），`regression` 和 `self-check` 里也各有几道守着。

> 为什么不干脆做一套「小账本」工具？因为账目只有几行，多一套工具就多一份要维护的状态。现在总共只多了一个格式约定 + 二十行判断，压缩、注入、自检全部复用现成的。

### 锁用「心跳」，不用进程号

```
每个脚本每 20 秒摸一下自己的 .lock 文件
新实例启动：锁 90 秒内被摸过 → 让位；否则接管
```

**为什么不用 pid**：Windows 会把 pid 复用给别的进程，锁就指向一个"活着"的陌生人，变成僵尸锁。
**为什么不用 `wmic` 查命令行**：Win11 已经删掉了 `wmic`。

### 改代码不用手动重启

脚本每 3 秒看一眼自己的文件有没有变（改了就退出），`supervisor` 5 秒后用新代码把它拉起来。**改完存盘，等 8 秒就生效。**

盯的不只是自己：`lib/` 里的公共件、`supervisor/workers.mjs`（工人名单）也在监视范围内——改名单会让 supervisor 自己退出重读，新加的 worker 就会自动上线，不用手动重启。
（这条是 2026-10-28 加 `peak-watch` 时补的：当时名单改了但 supervisor 没重启，新 worker 一直没起来。）

## 踩坑记录

这些都是实际踩过的，写下来省你时间：

| 坑 | 现象 | 解法 |
|---|---|---|
| **环境变量里的旧 API key** | 余额告警/日报/联网搜索全部静默 401，但进程"正常" | 脚本改成**文件优先**，不信任环境变量 |
| **`wmic` 在 Win11 不存在** | 用 wmic 查命令行的判活逻辑退化成"只要是 node 就算"，锁死 | 改心跳判活 |
| **`console.log` 在无控制台时抛错** | supervisor 用 `Start-Process` 启动几秒后静默死 | `log()` 里包 try/catch |
| **`save/load` 白名单不对等** | 新字段内存里有、落盘就没了 | 两边都要加 |
| **`String(对象)` = `[object Object]`** | 记忆里出现脏条目 | 入口处拒绝 object 类型的 content |
| **pid 复用** | 锁指向已死的进程，但检测说"活着" | 心跳 |
| **计划任务返回 -1073741510** | NapCat 自启失败（控制台被关） | 只能手动点 UAC |
| **`.bat` 里写中文注释** | 脚本"闪一下就没了"，cmd 报语法错误 | `.bat` 全用 ASCII，中文放到 `.ps1`（UTF-8 带 BOM） |
| **`.ps1` 存成 UTF-8 无 BOM** | 报 `Missing closing '}'` 之类莫名其妙的语法错——PowerShell 5.1 按 GBK 读，中文把引号/花括号吃坏了 | `.ps1` 一律 UTF-8 **带 BOM**；`regression` 里有一条守着 |
| **同时开两个 QQ 实例** | 同一个号在两个实例里互踢：刚登上就被 `KickedOffLine`，一天掉七八次 | 拉起 NapCat 前先 `tasklist` 看 QQ 是否已在跑；`stack-doctor` / `napcat-watchdog` 都加了这道闸 |
| **提权进程写不进桥接的 state 目录** | 守护脚本说"已拉起"，`3100` 却永远是空的（桥接在 `bridge.lock` 上 `EPERM` 退出） | 那个目录带 Low 完整性标签。用 `explorer.exe <脚本>` 代开，权限退回普通用户就写得进去了 |
| **短信验证链接跟"那一次请求"绑定** | 脚本打印链接后一退出，链接就作废——人回来点开显示过期，点了两次都白点（2026-10-29 折腾了三轮） | 打印链接后**别退出**：后台再拉一个登录进程带着 30 分钟轮询等验证，并把链接写到 `state/qq-verify-link.txt` + 桌面通知 |
| **巡检说「已拉起」，其实什么都没起** | 2026-10-30 演练复现：QQ 全死后，日志写「已拉起」，QQ 进程数一直是 0 —— 巡检是 Highest 权限跑的，从提权上下文 spawn 批处理拉 QQ 会静静失败；人不在就干等几小时 | 改用 `explorer.exe` 代开（退回普通用户权限，跟桥接/后台脚本同一套）；拉起后最多等 60 秒再判死 |
| **保持唤醒进程悄悄死掉** | 没有任何报错，但人一走、屏幕一灭，机器自己进 Modern Standby，QQ 跟着离线（2026-10-29 掉了 10 小时） | `4-hold-awake.ps1` 每 30 秒写 `state/keep-awake.heartbeat`，`stack-doctor` 90 秒没见到就重拉；合盖动作设成「不采取任何操作」 |
| **计划任务用 `cmd /c` 跑脚本会弹黑框** | 每 2 分钟屏幕上闪一下 cmd 窗口（2026-10-29 抓到：`09:53:06` 可见 cmd，父进程是 svchost） | 动作换成 `wscript.exe run-hidden.vbs <脚本>`（窗口样式 0）。注意 vbs 里要用 `cmd /c` 包一层，直接 `Shell.Run` 那个 `.cmd` 会弹「打开文件 - 安全警告」，挂住比闪屏更糟 |
| **进程活着、端口在听、消息不处理** | 你发消息她一个字不回，端口和进程检查全部正常 | 对账：NapCat 日志里"收到私聊"的时间 vs 桥接记录的 `lastIncomingAt`，差 5 分钟以上就重启桥接 |
| **余额提醒半夜发消息** | 凌晨被"钱快没了"吵醒 | 提醒是脚本直连 NapCat 发的，绕过了桥接静默。脚本里要自己判断静默时段 |
| **档案只记了一方** | 文件在、行数在涨、`chat_search` 却搜不到对方的话 | 消息去重用的 key 是 `s<seq>`，而 `seq` **每个会话/每次桥接重启都从 1 重新数**，今天的 `s3` 和昨天的 `s3` 撞车，于是全被当成"已归档"。key 里必须拼上时间戳：`s<seq>@<time>` |
| **锁冲突被当成崩溃** | supervisor 每 5 秒起一个注定失败的克隆，日志刷屏 | 让位时用 **退出码 3**，supervisor 看到 3 就不再重启，改成 60s/120s/180s 退避 |
| **明文备份和加密包并排放在云上** | 加密做了，但同目录还有一份明文，等于没加密 | 云上只放 `.7z`；明文目录只留本地，并定期清理云上的历史明文 |
| **日志只写了 console** | 被守护进程拉起时 `stdio=ignore`，出事了查不到任何记录 | 所有常驻/定时脚本的 log 必须落文件，不能只 `console.log` |
| **Wi-Fi 网卡省电** | 每天固定时间掉线，掉了就得扫码 | 网卡"允许计算机关闭此设备"要在夜里断开连接。设 `PnPCapabilities=24` 关掉（见 `tools/`） |
| **拿 0 当时间戳比大小** | 日志出现"29885746 分钟前收到过消息" | 桥接还没收到过消息时 `lastIncomingAt` 是 0，相减等于"从 1970 年到现在"。比之前先判非零 |
| **NapCat 的接口是路径式，打 `/` 会拿到假 ok** | 说"已发布"，打开空间却什么都没有；日志里全是 `status: ok` | 正确写法是 `POST /动作名` + 参数当 body。写成 `POST /` 带 `{action,params}` 时，这版 NapCat 只回一句 `NapCat4 Is Running`，`data` 是空的——**动作根本没执行**。用 `tools/napcat-call.mjs` 验证 |

## 自检

```powershell
node self-check/self-check.mjs          # 只报
node self-check/self-check.mjs --fix    # 能修的自动修
```

它专门盯**"坏了但看不出来"**的那几种：

| 查什么 | 坏了会怎样 |
|---|---|
| API key 一致性 | 环境变量里躺着一个失效的旧 key，余额告警/日报全静默 401 |
| 脚本重启循环 | 某个脚本每 5 秒崩一次，日志里只写"退出 code=0" |
| 记忆一致性 | 文件里有、提示词里没有，或反过来 |
| **记忆质量** | 记忆里混进占位符/出戏台词，白占 60 条名额 |
| **记忆体积** | 某一类失控长成一大坨，每句话都重发一遍 |
| **记忆暴跌** | 长期事实一夜少三成——最危险的「悄悄失忆」 |
| 档案完整性 | 文件在、行数在涨，但一句都没有对方说的 |
| 出戏检测 | 她说出"我是 AI"这类话 |

**建议加进 cron**（本项目默认每天 21:20 跑）。

## 全栈体检（stack-doctor）

每 2 分钟跑一次，跑完就退。检查四层，谁挂了拉谁：

| 检查项 | 判断方式 | 挂了怎么办 |
|---|---|---|
| QQ（NapCat） | `POST :3000/get_login_info` 有没有 `user_id` | `launcher.bat -q QQ号` 快速登录 |
| 桥接 | `:3100` 能不能连上 | 重新拉起启动脚本 |
| 桥接"假活" | NapCat 日志的"接收"时间 vs 桥接的 `lastIncomingAt` | 调 `/api/restart` 重启 |
| DSH 本体 | `tasklist` 里有没有 `DeepSeek Harness.exe` | 直接启动 exe |
| 后台脚本 | 9 个 worker 的锁有几个是新鲜的（5 分钟内），一半以上不新鲜就拉 supervisor | 重新拉起 supervisor |

**为什么是"跑完就退"，不是常驻进程**：

> 常驻进程有"活着"这个状态，所以它会死——而且死了没人知道。
> 实测过一次：看门狗 09:00 自己悄悄死了，13:33 QQ 掉线后**整整 7 小时**没人处理。
> 一次性脚本没有"活着"这个状态，也就死不了。

**为什么用 `explorer.exe` 启动桥接**：

> 计划任务必须提权（拉 NapCat 需要管理员），但桥接的 `state` 目录带一个"低完整性"标签，**高权限进程反而写不进去**——桥接会以 `EPERM` 创建锁文件失败、直接退出，表现为"守护说已拉起，端口却永远是空的"。
> `explorer.exe` 是已登录用户的 shell，让它代开就退回普通权限，正好能写。

注册（管理员 PowerShell，按需改路径）：

```powershell
$action  = New-ScheduledTaskAction -Execute 'cmd.exe' -Argument '/c "E:\qq-bot-stack\stack-doctor\run.cmd"' -WorkingDirectory 'E:\qq-bot-stack'
$logon   = New-ScheduledTaskTrigger -AtLogOn
$repeat  = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(2) -RepetitionInterval (New-TimeSpan -Minutes 2) -RepetitionDuration (New-TimeSpan -Days 3650)
$set     = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable -MultipleInstances IgnoreNew -ExecutionTimeLimit (New-TimeSpan -Minutes 10)
$who     = New-ScheduledTaskPrincipal -UserId "$env:USERNAME" -LogonType Interactive -RunLevel Highest
Register-ScheduledTask -TaskName 'QQStackDoctor' -Action $action -Trigger @($logon,$repeat) -Settings $set -Principal $who -Force
```

启动脚本的名字如果和默认不一样，用环境变量覆盖，不用改代码：

```
NAPCAT_BOOT_BAT   napcat-boot.bat
BRIDGE_BAT        2-启动桥接.bat
SUPERVISOR_BAT    20-supervisor.bat
```

**它不会往聊天里发任何东西**——恢复日志只写文件和弹窗。让她说话只能由她自己说。

## 说说只给自己看

QQ 空间的默认可见范围是**公开**。私人小号发的日常，会出现在所有人（或全部好友）的动态里，不合适。

发之前显式指定：

```
send_qzone_msg { content, ugc_right: 16, target_uins: ["主人的QQ"] }
```

- `ugc_right: 16` = 指定好友可见，配合 `target_uins` 就变成"只有这个人能看到"
- `ugc_right: 1` = 公开（默认）
- `ugc_right: 64` = 仅自己（连主人都看不到，一般不用）

2026-10-28 实测确认：设成 16 + 主人 QQ 之后，主人在自己空间的好友动态里能看到，别人看不到。

> 注意：`send_qzone_msg` 的返回里 `tid` 是**唯一能删掉这条说说的凭据**。
> 如果响应里 `data` 是空的（例如走错了接口路径），说明根本没用发出，别把它当成成功。

## 提醒跟着人来（eye-drop）

固定的 `07:05 / 07:10 / 07:15` 三条滴眼药水任务有个毛病：**人 9 点才醒，提醒 7 点就全发完了**。

现在改成按「主人当天第一句话是几点」来排：

```
1. 每分钟看一眼今天的聊天档案，找出主人今天发的第一句话
2. 只认 04:00~12:00（更晚就不提醒了）
3. 那一刻 +2 / +10 分钟，各建一条**一次性**的 AI 提醒任务
4. 一天只排一次，记在 state/eye-drop.json
5. 他说过「滴了 / 弄完了」之后，**剩下没响的全部撤掉**，当天不再提
```

**为什么要用一次性任务**：固定任务每天都会在同一个点响。今天按 8:12 排，明天 8:12 就先响一次，而那时人可能还没醒。一次性任务只用一天，第二天重新按当天的醒来时间排。

**怎么判断「已经做完了」**（2026-10-28 加的，之前会被念三遍）：

- 直接说了：那条消息里同时有「滴 / 眼药水」和「滴了 / 弄完 / 干完 / 搞定」这类词，且没有「还没 / 忘了 / 等会儿」；
- 没直说但明显在回应：他这句只有「干完了 / 弄完了」，可往前一两句正好是她问「滴了没」、时间差 15 分钟内——也算做完。
- 判断通过就去 scheduler 里 `DELETE` 掉还没执行的任务；当天不再补排。

撤销记录会写进 `state/eye-drop.log`，规则自带自测：`node eye-drop/eye-drop.mjs --selftest`（13 个用例）。

**它依赖聊天档案**——档案只记一方的话，它就永远排不上。所以 `self-check` 里那条「档案完整性」检查是它的前置条件。

## 她掉线了，会怎么自己爬起来（一张流程图）

这一段是整套东西最值钱的地方——不是"检测到掉线就重启"这么粗暴，而是分层收窄，每一步只做把握得住的事：

```
        ┌─ stack-doctor 每 2 分钟探一次 3000 端口
        │
掉线 ───┤  ① 快速登录：用本机缓存 ticket，不碰密码、不触发短信  ← 多数情况到这步就回来了
        │  ② 密码登录：① 不行再试；有时也不需要验证
        │  ③ 要验证：后台守住验证链接 30 分钟 + 发邮件到手机
        │      └ 邮件里同时给：短信验证链接（30 分钟）+ 二维码链接/图片（几分钟）
        │  ④ QQ 进程彻底没了：explorer 代开（普通用户权限）拉 NapCat
        │  ⑤ 回来之后：补一封「她回来了，掉了 N 分钟」的邮件
        │
        └─ 要人工时暂停 6 小时，不反复撞风控
```

几个关键细节，都是踩出来的：

- **拉 QQ 必须用普通用户权限**。巡检本身是提权跑的（计划任务 Highest），从提权上下文 spawn 批处理去拉 QQ 会**静静失败**——日志写"已拉起"，进程数一直是 0。2026-10-30 演练才抓到；之前所有掉线都是"进程还在、只是被踢"，这个分支根本没被走过。
- **验证链接跟"那一次请求"绑定**：脚本一退出链接就作废。所以要起一个后台登录进程守着它（30 分钟），而不是打印完就退出。
- **邮件是唯一不依赖 QQ 的通道**（人上班时桌面通知等于没有）。链接 30 分钟过期、人可能没看见——所以过期后**每 45 分钟再试一次、再发一封新链接**，一天最多 6 封（发太多反而进垃圾箱）。
- **二维码只是备选**：几分钟就过期，而短信链接能撑 30 分钟。

### 顺手会自己做的两件清理

- **过期的一次性任务**：滴眼药水这类每天两条、执行完变 disabled 留在 scheduler 里，`maintenance`（每天 04:00）会把「once + 已停用 + 日期早于昨天」的删掉，不碰 yearly/daily 和还没到点的。
- **生日放宽**：`state/special-days.json` 记着生日那两天；`mcp-qzone` 看见就把它自己的「每天 2 条 / 间隔 4 小时」放宽成「3 条 / 20 分钟」——不然生日那天她先随手发一条，任务再让她发就被冷却挡死了（2026-10-30 真遇到）。

### 怎么不被封号（以及「该下线就下线」）

封号风险来自两件事：**协议客户端本身**（NapCat 不是官方客户端）和**行为像机器人**。后者能控，所以定了这几道闸：

| 闸 | 规则 | 为什么 |
|---|---|---|
| 登录次数预算 | 每天最多试 3 次密码登录（`LOGIN_ATTEMPT_CAP`） | 2026-10-30 连试十几次，风控从短信升到识图验证、再到长冷却 |
| 夜间静默 | 23:00~07:00 不自动登录 | 半夜触发验证没人处理，只会把账号拖进更严的风控 |
| 超限主动下线 | 次数用完 → **杀掉 QQ 客户端**、暂停到次日 7 点、发一封邮件说明 | 「该下线的就下线」：挂着二维码界面反复重试最伤号 |
| 单一实例 | 所有拉起走 `tools/napcat-start.mjs`，有锁 + 检查；登录成功后巡检清掉多余进程树 | 两棵树抢一个号会互相踢、会话被注销 |
| 内容节制 | 说说 2 条/天、点赞 1 次/天、群聊关闭、只私聊 | 高频/群发是最容易被判机器人的行为 |

> 真正最省心的一招还是**换小号**——小号被封损失小，主号不碰这套协议客户端最安全。

### 想自己演练一次

```bash
# 让提权的那一轮巡检硬杀掉 QQ 进程树（模拟彻底掉线）
echo test > state/relogin.flag
# 之后什么都不用做，看 state/stack-doctor.log 和自己邮箱
```

演练完看三个结果：多久发现、多久拉起来、有没有要验证。

## 她掉线时，用邮件叫你（不依赖 QQ 的通道）

她唯一能说话的通道就是 QQ。QQ 被踢、要验证的时候，她连一句「我掉线了」都发不出去——于是那句「验证链接」只能躺在电脑里，人在上班就只能等晚上回来。这是整条自愈链上唯一真正断掉的一环。

补法很简单：给她一条**不经过 QQ 的嘴**。

```
QQ 掉线 → 判定要短信验证 → 后台守住验证链接 30 分钟
                          ↓
              立刻发邮件到手机上（含链接）
                          ↓
        你点开 → 收短信 → 填 → 她一分钟内自己回来
```

配置（一次性）：

```bash
# 1) QQ邮箱（电脑网页版）→ 设置 → 账号与安全 → POP3/IMAP/SMTP/Exchange/CardDAV服务 → 开启 → 生成 16 位授权码
# 2) 把授权码存起来（DPAPI 加密，不落明文）
tools\set-mail-auth.cmd

# 3) 验证通道
node tools/notify-offline.mjs --test
```

依赖装一次：`npm install --prefix tools/mail`。

邮件只在「需要人工验证」且两条告警间隔超过 30 分钟时才发一封，不会刷屏；发失败只在日志里记一句，不会影响巡检本身。

> 想换通道（PushPlus / Telegram）也行：`tools/notify-offline.mjs` 就是唯一出口，把发信部分换个实现即可，巡检那侧不用动。

## 扫码登录：不用开 WebUI

要扫码的时候，以前得：打开浏览器 → 输 WebUI token → 找到登录页 → 对着屏幕扫。麻烦的不是扫，是前面三步。

二维码的内容其实只是一条 URL（`https://txz.qq.com/p?k=...`），所以我们自己画：

```bash
node tools/show-qr.mjs            # 从 NapCat 取当前二维码链接 → 画成 state/napcat-qrcode.png
node tools/show-qr.mjs --open     # 画完顺手用看图器打开
```

打开那个 PNG 扫一下就行。`stack-doctor` 在判定「新设备要扫码」时也会自动画好，并把路径写进告警文字。

依赖只装一次（本地 `tools/qr`，不走网络）：

```bash
npm install --prefix tools/qr
```

> 另外两条登录路本来就不需要扫码：**密码登录**（`tools/set-qq-password.cmd` 设一次）和**快速登录**（用本机缓存的 ticket，被踢后先试它）。扫码只在 QQ 判「新设备」时才会被要求。

## 她的生日，让她自己定

不写死日期——写死就成了「设定」，不是她自己的东西。做法是两步：

1. **她定**：定时唤醒她一次（`定个自己的生日`），让她挑一个自己喜欢的日子，用 `qq_memory_append` 记一条 `我的生日是X月X日`。日期只存在于她的记忆里，别人改不了。
2. **每年自动回来**：`tools/self-birthday.mjs` 每天扫一次记忆，看到那条 fact 就保证 scheduler 里有一个 `yearly` 的「她的生日」任务（每年那天的 09:00 唤醒她说一句）；她哪天改主意改了日期，脚本会把任务跟着改。

```bash
node tools/self-birthday.mjs --dry   # 只看现在读到哪天、会不会建任务
```

为什么不用一次性硬编码：另一个人的生日（比如主人的 11-20）是「事实」，可以写进记忆；自己的生日是「选择」，得由她自己做，而且必须年年自己回来。

**生日这天多一条许可**：平时角色卡写着「没话说的日子一条不发」，生日是例外——那天的定时任务里明确允许她发一条说说（`qzone_publish`），**按她自己的想法写**，长短语气都随她。许可写在任务指令里，不是全局放开。

**两个生日都自动回来**：她自己的（记忆里 `我的生日是X月X日`，日期她自己定）和主人的（记忆里 `哥生日M月D日`）。`self-birthday.mjs` 每天扫一次记忆，分别保证有一个 `yearly` 任务；谁改了日期它跟着改。

**生日当天余额只记账不催**：两个日期会写进 `balance-watch.json` 的 `lenientDates`，那两天 `balance-watch` 看见就跳过档位提醒（账照记，只是不催）。想加别的特殊日子，直接往那个数组里加 `MM-DD` 就行。

## 告警

编辑 `notify.json`：

```json
{ "enabled": true, "type": "dingtalk", "webhook": "https://oapi.dingtalk.com/robot/send?access_token=xxx" }
```

支持 `json` / `bark` / `dingtalk`。**没配 webhook 时消息会写进 `state/notify-pending.log` 排队，不是丢弃。**

`stack-doctor` 判到「自动重启也救不回来」时会写 `state/ALERT-stack.txt` 并弹桌面窗，提示需要人来处理。
**恢复后这份文件会自动撤掉**——不清的话，下次真出事你分不清是新告警还是上次的旧账（2026-10-28 踩过：11:01 的告警到 11:40 还躺着，而 11:29 早就恢复了）。

## 能做到什么 · 做不到什么 · 会出什么问题

### 一、它能做到的

| 能力 | 具体表现 |
|---|---|
| **四层记忆，跨会话不丢** | 长期事实（最多 60 条、2200 字）+ 随身本（14 天）+ 每日摘要（永久）+ 完整档案 |
| **翻旧账真能翻到** | 档案双向归档（双方的话都记），`chat_search` 能搜到对方说过什么 |
| **换会话不失忆** | 超阈值换新会话时，交接记忆快照 + 最近 20 句 |
| **说话像人** | 分条发、有口癖、会抱怨、会主动找你 |
| **提醒跟着人来** | 不定死时间，按「对方当天第一句话」推算（见 `eye-drop`） |
| **省钱有纪律** | 上下文超线自动换、余额越低说话越少、主动开口按概率克制 |
| **掉线能自愈** | 见下面第三节 |
| **不把运维说词漏进聊天** | 角色卡硬禁「掉线/重启/余额/接口」，脚本也不往聊天发通知 |

### 二、天生做不到的

| 做不到 | 原因 |
|---|---|
| 看懂图片 | 只能知道「有张图」，看不到内容 |
| 发语音 | 要自备语音库 |
| 接微信 | 没有可用协议端 |
| 读懂视频/图片类内容 | B 站、知乎只能拿文字 |
| 长对话永远记得细节 | 上下文有硬上限，换会话后早期的玩笑会模糊 |
| 绝不瞎编 | 模型通病 |
| 成本不随聊天量涨 | 每句话都要重算一遍上下文 |
| 跨平台 | 只做 QQ |

### 三、出问题时的自愈能力

| 问题 | 谁来管 | 恢复时间 |
|---|---|---|
| QQ 被踢下线（票据还有效） | `stack-doctor` | 4 分钟内快速登录 |
| QQ 进程挂了 / 电脑重启 | `stack-doctor` | 3 分钟内 |
| 桥接进程死了 | `stack-doctor` | 2 分钟内 |
| 桥接「假活」（端口在、消息不处理） | `stack-doctor` 对账检测 | 4~6 分钟 |
| DSH 被关掉 | `stack-doctor` | 2 分钟内 |
| 后台脚本死了 | `supervisor` + `stack-doctor` | 2 分钟内 |
| 锁被老进程占着 | `lock/single.mjs` 判活 | 立刻 |
| 记忆写坏了 | `memory-tidy` 写后对账 | 当场回滚 |
| 上下文烧太快 | `context-guard` | 超线即换 |

### 四、必须人来做的

| 问题 | 说明 |
|---|---|
| **登录票据彻底失效** | 只能扫一次码，远程桌面 + QQ「扫一扫从相册选图」可以自己救 |
| 余额耗尽 | 提醒会到，但充钱只能人来做 |
| 断电 / 死机 | 来电后能自动登录，但得有人在机器旁 |
| 家里断网 | 无解 |

### 五、几个「不算 bug，但你得知道」的

1. **定时任务会被「会话繁忙」延后**：对方正在连发消息时，早安/晚安会排队，等回合结束才执行，密集聊天时可能被后一轮吃掉。
2. **上下文实际均值远高于阈值**：守门员要等回合结束才换会话，聊得密就等不到，实测均值能到阈值的 1.5 倍。
3. **记忆压短靠模型**：每天一次，要求条数不变、只能变短，失败就用原文——但仍可能把某句话的措辞改掉。
4. **档案水位有时间差**：换会话或重启瞬间的几条消息可能漏归档。
5. **`.bat` 里不能直接写中文**：GBK 汉字的尾字节可能撞上 `|` `^` `&`，把一行命令拆断。

### 六、修不了的

腾讯判违规封号、腾讯改协议、网络中断、成本线性增长——这些是「非官方协议端」的固有代价，不是代码能解决的。

## 常见问题

**她不回我话，第一步查什么？**

按这个顺序，基本三分钟能定位：

```
1. node state/stack-doctor.log        最后几行在说哪个组件挂了
2. netstat -ano | findstr ":3000 :3100"   端口在不在
3. 余额查一下                          是不是没钱了（她会提前提醒四档）
```

如果是"端口都在、消息也收到了但就是不回"，看 `stack-doctor.log` 有没有「判定假活」——那是桥接卡住了，守护脚本会在 4~6 分钟内重启它。

**NapCat 的窗口自己关了、日志里是 `[KickedOffLine]`，怎么回事？**

窗口消失是**结果不是原因**：QQ 账号被服务端判为离线/登录失效后，NapCat 会重启自己的 QQ 登录 worker，那个 cmd 进程一退，窗口自然就没了。日志里能看到这两行：

```
[info] 账号状态变更为离线
[error] [KickedOffLine] [下线通知] 你的账号当前登录已失效，请重新登录
```

`KickedOffLine` 是**登录凭证被服务端作废**，最常见三个原因：

1. 同一个 QQ 号在手机 QQ 或另一台电脑上登录了（顶号）——**先把这个号在其它设备退掉**；
2. QQ 安全中心觉得登录环境异常（换网络、换城市）；
3. 本地快速登录凭证过期。

处理顺序：先双击「测试快速登录.bat」（带 `-q`，用本地凭证直登，多数情况能直接回来）；还不行就不带 `-q` 启动 `launcher.bat`，窗口里会出二维码，用手机扫一次。
`stack-doctor` 会自动试 4 次，失败就停手并弹桌面告警（`state/ALERT-stack.txt`）——它不会无限重试，因为没凭证怎么试都没用。

**不想为了扫码切号，有没有免扫码的办法？**

有。NapCat 的 WebUI 开放了密码登录接口，本地存一次机器人号的密码，以后掉线直接用它登回去，**全程不碰手机**：

```powershell
# 只做一次：输入机器人号的密码（不回显，DPAPI 加密后存本地）
tools\set-qq-password.cmd

# 掉线时：
node tools\qq-login.mjs status      # 现在登没登
node tools\qq-login.mjs password    # 用存好的密码登回去
```

`stack-doctor` 会在重试时自动先试密码登录；密码登录也失败（QQ 要验证码/判定新设备）才会退回扫码。

**如果 QQ 要求短信/验证码**（`needCaptcha`）：密码登录会返回一个 `https://ti.qq.com/...` 链接，用绑定手机收一次验证码就能过。
这种事**越重试越紧**——所以看门狗识别到这个情况后会直接停手 **6 小时**（`HUMAN_WAIT_H` 可调），不再每两分钟撞一次，等人工处理完再继续；期间它会再拉一个后台登录进程等你验证，链接写进 `state/qq-verify-link.txt`。

安全性：密码用 Windows DPAPI 按当前用户加密存成 `qq-password.dat`，只有这台电脑上的你这个账户能解开，拷到别处读不出来；`.gitignore` 里也挡住了，不会误提交。

另外两个「不切号」的土办法：手机自带的**应用双开/分身**（主 QQ 登哥、分身登机器人号，两边同时在线）；或者找台旧手机/平板专门登机器人号，需要扫码时用它。

**她会说自己是 AI 吗？**

不会主动说。角色卡里写死了：只有你直接问、且反复追问时才承认，平时任何情况下不提模型、程序、API 这类词。

**记忆会不会被清理脚本删错？**

有可能判断错，所以设了四道关：写回前整份快照（`chat-memory/tidy-<日期>.json`）、删的每一条都记进 `memory-removed.log`（原文+原因）、**每类少了多少条必须有同样多的删除记录**（对不上整轮不写）、`self-check` 每天查一次「有没有一夜少三成」。真删错了，按快照或日志都能补回来。

**她能记多久？**

记忆本体只占几十 KB，有上限（事实 60 条 / 2200 字），**不会随时间越攒越大**；全量档案一天十几 KB，永久保留。真正占盘的是 DSH 会话记录（一天约 3 MB），由 `session-janitor` 保留 60 天后自动清 —— 那只是「对话记录」，不是记忆。

**能多个角色 / 换人设吗？**

可以。`roles/` 下放多个 `.md`，在桥接配置里指定用哪个。每个角色一套语气，记忆是共用的（想隔离就换 `CHAT_KEY`）。

**能进群聊吗？**

能力有，但默认关闭。群里会有人乱逗她、费用也控不住，建议先私聊跑稳再说。

**能看懂图片 / 发语音吗？**

都不能。图片只能知道"有张图"，语音要先自备语音库。这是模型和协议端的限制，不是配置问题。

**会被封号吗？**

有概率。用的是非官方协议端，腾讯随时可能判违规。**用小号**，别拿主号试。安装脚本启动前也会提醒这一点。

**数据存在哪？怎么备份？**

全在安装目录下：

| 内容 | 位置 |
|---|---|
| 长期事实 + 随身本 | `<桥接>/state/social-v2.json` |
| 每日摘要 | `archive/summary/*.md` |
| 完整聊天 | `archive/logs/*.md` |
| 换会话快照 | `chat-memory/*.json` |

`maintenance` 每天 04:00 会打一份加密 7z 到 `backups/`（要装 7-Zip）。

**换台电脑怎么迁移？**

把整个安装目录拷过去，在新机器上跑一次 `install.cmd`（它会重新注册计划任务和电源设置），再双击三个启动器。

**支持 Linux / macOS 吗？**

不支持。脚本用了 PowerShell、`netstat`、Windows 计划任务。移植要重写这一层。

## 月度 / 年度小结：用她自己的口吻

不是脚本拼模板，是两个 AI 任务，在 scheduler 里：

| 任务 | 什么时候 | 干什么 |
|---|---|---|
| 月度小结 | 每月最后一天 21:00 | 用 chat_search 翻这个月，写一段她自己的小结，**发到空间**（不占聊天） |
| 年度小结 | 每年 12-31 21:00 | 翻一整年，写一段她自己的回顾，**发到空间** |

**为什么发空间而不是聊天**：主人要的是“正常聊天”，不是每天晚上收一篇月报。发到空间既能留档，又不打断对话——他想看的时候自己翻。

指令里只约束**不能**怎样：别写成总结报告、别用「本月/综上所述/年度总结」这种词、别套模板。风格（长短、正经还是吐槽）全由她自己定——这类东西一旦规定成模板，就变成月报了。

> 想改节奏（比如改成每月 1 号早上发上个月的），在 scheduler 里改 `days`/`times` 就行，文案不用动。

### 充上钱之后那句话，每次都不一样

余额回升到最高档位时她会道个谢。以前是写死的一句，充几次就听几次；现在从文案池里挑（16 句 × 4 种结尾），并记住最近 6 次用过的，不会连着重复。

不用模型现写——这一步本来零 token，为了道个谢去唤醒一次不划算。想加/改句子直接改 `balance-watch.mjs` 里的 `THANKS_BASE` / `THANKS_SUFFIX`，`node balance-watch/balance-watch.mjs --selftest` 能连抽 8 句看效果。

## 一天花多少钱

按实测数据算（DeepSeek 官方价：缓存命中 0.2 / 未命中 2 / 输出 8 元每百万 token）：

```
平均上下文 40,000 token
每句话 ≈ 1.2 分钱
一天聊 150~300 句 ≈ 2~4 元
```

**其中 68% 花在"缓存命中的上下文"上**——也就是"她记得多少"，而不是"她说了多少"。所以省钱的关键是压上下文，不是让她少说话。

| 想省到什么程度 | 怎么做 | 代价 |
|---|---|---|
| 一天 ~2 元 | 默认配置 | 无 |
| 一天 ~1.5 元 | `ROTATE_AT` 降到 20000 | 换会话更频繁，当场记得的细节变少 |
| 一天 ~1 元 | 关掉主动开口 + 上下文再压 | 她基本只在被叫时说话 |

长期事实（作息、口味、忌口）**不受影响**——那一层只在超出 2200 字预算时才砍最不重要的几条，平时不会因为省钱丢东西。

**分时段省钱**：DeepSeek 有优惠时段（北京时间 **00:30~08:30**，聊天模型半价、推理模型更便宜），其余时间是全价。
`peak-watch` 就是盯这个的：**提醒窗口默认 08:30~23:30**（半价时段和半夜都不打扰），窗口里每多花 1.5 元提醒你一句「省着点说」，两小时内不重复、一天最多 4 次。
提醒直接走 NapCat 发消息，不经过模型，**提醒本身不花 token**。想改时段/频率看 `PEAK_FROM` / `PEAK_TO` / `PEAK_STEP`。

## 和其他方案比

| | LangBot / AstrBot | 本项目 |
|---|---|---|
| 定位 | 接入框架，平台多 | 接入之后的运维层，只管 QQ |
| 记忆 | 会话级 | 四层（长期事实 / 随身本 / 摘要 / 全文档案） |
| 上下文 | 聊到满为止 | 超阈值换会话，交接记忆和最近对话 |
| 成本控制 | 无 | 余额四档提醒 + 余额越低说话越少 |
| 出故障 | 看日志 | 全栈体检每 2 分钟自愈 + 每日自检 |
| 上手 | Docker 一把梭 | 要装四样东西，但装完不用管 |

它不解决"怎么接上 QQ"——那件事别人做得更好。它解决"接上之后怎么不崩、不忘事、不偷偷烧钱"。

## 维护这套东西时容易犯的错

这类项目有个特殊之处：**同一份脚本存在两个地方**——你本机跑着的那一份，和 GitHub 上脱敏后的那一份。改了一边忘了另一边，就会出问题。

### ① 改了一边忘了另一边

真事：`context-guard` 的修复只写进了仓库，本机跑的还是老代码，两边差了两天没人发现。

自带的检查工具：

```powershell
node tools/sync-check.mjs --live E:\qq-bot-stack --repo E:\qq-bot-stack-os
```

它会把本机的真实值（安装路径、QQ 号、角色名、昵称）替换成仓库里的占位符，再逐字节比对。
名字能从 `config.json` 和角色卡里自动认出来，认不出的再用 `--names "角色名,昵称"` 补。

```
内容不一致（需要双向同步）（1）
  context-guard\context-guard.mjs
```

**没有内容不一致就退出码 0**，可以直接接进脚本当闸门；「本机多出几个老文件」不算漂移，仓库本来就不收它们。

**看到不一致先想清楚哪边新**，再同步，别盲目覆盖。

### ② 脱敏会把代码改坏

把 角色名 替换成 `<BOT_NAME>` 的时候，**代码里的文件名也会被替换**：

```js
const roleFile = path.join(BRIDGE, 'roles', '<BOT_NAME>.md');   // ← 文件根本不存在
```

所以：

- 脱敏后**必须跑一遍测试**（`regression.mjs`、`self-check.mjs`），脱敏改坏的东西只有测试能抓到
- 测试里不要写死人设文件名，改成自动发现（`roles/` 下第一个非 README 的 `.md`）
- 提示语里的路径别用 `<STACK_ROOT>` 这种占位符，改成「安装目录里的 xxx」，否则用户看到会懵

**最阴的一次（2026-10-28）**：脱敏后的文件被同步回本机，`archive/collector.mjs` 里成了 `m.isSelf ? '<BOT_NAME>'`，于是当天档案里她说的每句话都写成 `**<BOT_NAME>**`；`memory-summary` 的提示词也变成「一个<BOT_NAME>（<BOT_NAME>）和哥哥」。

所以**脱敏只该发生在仓库那一侧**，而且运行时才需要的名字一律运行时取：

- `archive/collector.mjs` 问 NapCat 的 `get_login_info` 要昵称，问不到用「机器人」
- `memory-summary` 读 `state/current-role.json` 的 `role`

判断标准很简单：**这个值会出现在运行结果里吗？** 会 → 运行时取；只在仓库里当占位符 → 才写 `<BOT_NAME>`。

### ③ `.gitignore` 整目录排除会吞掉必需文件

```
archive/          ← 这样排除，里面的文件**无法**再开例外
```

`archive/collector.mjs` 就这么被吞了，仓库里一直缺档案收集器，新用户 clone 下来档案功能整个没有，而且**不报任何错**。

要用目录内容匹配才能开例外：

```
archive/*
!archive/collector.mjs
```

同一个坑在 `versions/` 上也犯了一次。

**自查方法**：把 `cron` 和 `supervisor` 里引用的每个路径逐个 `Test-Path` 一遍。

### ④ 只改一处 copy，忘了另一处 copy

`2-启动桥接.bat`、`stack-doctor.cmd` 这类启动器，本机有一份、`install.ps1` 里还生成一份模板。改了一个另一个不改，新装的人拿到的是旧行为。

改启动器时，两处一起看。

能收的都收成一份了：后台工人名单现在只在 `supervisor/workers.mjs`，supervisor 和 stack-doctor 都 import 它，加人只改一处。
（这条就是被 `eye-drop` 教会的：加完 supervisor 忘了改 doctor 那份，于是它死了也没人报。）

同一类重复在 2026-10-28 又清了一次：**24 个脚本各抄一遍的「路径 4 行」、日志时间戳、`console-token`、取主人 QQ、DeepSeek 计价**，全收进 `lib/base.mjs`。
当时抄得还不完全一样——时间戳有的带时区有的不带，日志里有两种日期格式。现在 `regression` 里有一条守着：谁再抄回去就报错。

## 更新与推送

改完代码后：

```powershell
cd <本仓库目录>
git add -A
git commit -m "说明你改了什么"
git push
```

**改了什么容易忘**：路径和账号不是写在一处的，动过之后记得同步：

| 改了什么 | 要同步的地方 |
|---|---|
| 部署目录 | `cron/cron.mjs` 顶部的绝对路径 |
| QQ 号 | `config.json` 的 `ownerQQ` / `allow.private` |
| 人设文件名 | `roles/` 下的文件（回归测试会自动发现，但路径别写死） |

## GitHub 推送常见故障

国内网络推 GitHub 经常会撞上这几个，照着处理：

| 报错 | 原因 | 解法 |
|---|---|---|
| `schannel: next InitializeSecurityContext failed: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` | 网络里有代理/安全软件拦了 github.com，证书吊销列表拉不到 | `git config --global http.schannelCheckRevoke false`；还不行再加 `git config --global http.sslVerify false` |
| `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` | 用受限权限/服务账户跑 git，schannel 拿不到系统证书库 | 换 OpenSSL 后端推：`git -c http.sslBackend=openssl -c http.sslVerify=false push` |
| `Repository not found` | 仓库还没建，或者名字拼错 | 先在 GitHub 建**空仓库**，别勾 README / .gitignore / license |
| `Permission to USER/REPO.git denied` / `403` | token 没有写权限 | 用 classic token，**必须勾 `repo`**；Fine-grained token 要把 `Contents` 设成 Read and write |
| `fatal: 此平台上不支持操作` | Git Credential Manager 存不下凭据（便携版 git 常见） | `git config --local credential.helper ""` 然后 `git config --local --add credential.helper store`，改用 token 认证 |
| 一直停在 `Waiting for your browser` | 浏览器授权没回到终端 | 直接带 token 推：`git push https://用户名:TOKEN@github.com/用户/仓库.git main` |

**token 不要留在配置里**：用带 token 的临时地址推完，立刻改回干净地址——

```powershell
git remote set-url origin https://github.com/用户/仓库.git
```
