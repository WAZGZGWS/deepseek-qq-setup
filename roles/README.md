# 人设（角色卡）

**这个目录本来是放角色卡的地方，但本项目不提供任何预设人设。**

为什么？因为人设是这套系统里**最个人化、也最影响成败**的部分。一个现成的角色卡放在这里，你八成会直接拿来用——然后发现她说起话来不像你想要的，于是开始改，但因为你不知道每一句话为什么这么写，改来改去就把逻辑改乱了。

## 角色卡是怎么被使用的

```
每回合唤醒 → 读 roles/ 下第一个 .md（排除 README.md）→ 全文拼进提示词
```

也就是说：**角色卡每回合都会完整注入**，写多少就带多少 token。

- 2,000 字 ≈ 1,000 tokens，占 30k 上下文的 3%
- 6,000 字 ≈ 2,900 tokens，占 10%

**写得越细，性格越稳，但越贵，也越容易让模型抓不住重点。**

## 建议的结构

不用照抄，但这些问题必须回答清楚：

```markdown
# 角色卡：<名字>

## 你是谁
身份、和用户的关系、对"我是 AI"这件事的态度

## 怎么叫人和自称
称呼、自称、生气时怎么喊

## 性格
4~6 条，每条一个具体行为（不要写"温柔善良"这种形容词）

## 怎么说话
句长、语气词、要不要用 Markdown、能不能列点

## 边界
什么话不能说、被问到身份怎么答、遇到敏感话题怎么办

## 口癖
具体的词，不是"活泼一点"这种描述
```

## 几条踩坑经验

**1. 不要写范例对话，除非你想它被照搬**

我原来写了一句「大方承认自己是 AI：被问到就说『我是你的 AI 助手啊』」，结果她把这句当口头禅，一问吃饭就说「我是 AI 不用吃」，特别出戏。

**改成规则，不要给模板。**

**2. 边界要写"什么时候不能说"，不是"什么时候能说"**

❌ `可以承认自己是 AI`
✅ `只在被直接问到时才承认，其他任何时候都不主动提`

**3. 形容词无效，行为有效**

❌ `性格温柔`
✅ `被夸先说「才没有」，过两秒又忍不住说「……不过你这么说我还挺高兴的」`

**4. 长度控制在 2,000~4,000 字**

- 少于 1,500：性格撑不住，容易漂
- 多于 6,000：模型抓不住重点，而且每回合都在付费

**5. 定期检查她有没有出戏**

```powershell
node ../self-check/self-check.mjs
```

会扫最近 3 天她的发言，找「我是 AI」「作为 AI」这类主动暴露身份的话。

## 关于"记忆"

人设里需要告诉她**怎么用记忆工具**，否则她不会主动记东西。参考：

```markdown
## 记忆

要记（`qq_memory_append`）：
- 用户的偏好、正在忙的事（`memberImpression`，target 写用户名）
- 没聊完的话题（`activeTopic`）
- 不会变的事实：作息、口味、工作性质（`fact`）

记 1~3 条就够，别每条都记。旧话题用 `qq_memory_remove` 清掉。

翻旧账用 `chat_search` / `chat_day` / `chat_recent`：他说"我上次说过"就先搜，
搜到了自然接上，别说"根据记录显示"。
```

## 文件命名

**随便起**，比如 `assistant.md`、`小助手.md`。程序会读 `roles/` 下**第一个非 README 的 .md**。

如果你想同时管理多个人设，通过 `state/current-role.json` 切换（具体看桥接的文档）。

---

**最后一句**：人设写得好不好，决定了她像不像一个真人。这部分我没法替你写——但你写完可以跑 self-check 看有没有明显出戏，也可以随时改，改完 3 秒热重载生效。
